# Card

The `<uds-card>` component groups related content — an image, heading, body text, and action buttons — into a single scannable unit. It supports card-as-link behavior (entire surface clickable) and a horizontal layout variant for wider contexts.

## Usage

```html
{/* Basic card */}
<uds-card heading="Research">
  <p>Discover faculty-led research opportunities.</p>
</uds-card>

{/* Card with image and actions */}
<uds-card heading="Apply Now" image="/images/apply.jpg">
  <p>Applications for Fall 2027 are open.</p>
  <uds-button slot="actions" label="Start Application" color="gold"></uds-button>
</uds-card>

{/* Card as a link */}
<uds-card heading="Visit" image="/images/tour.jpg" href="/visit">
  <p>Schedule a campus tour.</p>
</uds-card>

{/* Horizontal layout */}
<uds-card heading="News" image="/images/news.jpg" horizontal>
  <p>Latest updates from the Sun Devil community.</p>
  <uds-button slot="actions" label="Read More" color="primary"></uds-button>
</uds-card>
```

## Do / Don't

### ✅ Do

- Use cards for scannable groups of related content (news, programs, events)
- Provide a heading that clearly identifies the card's topic
- Use `href` when the card should navigate to a detail page
- Limit actions slot to 1–2 buttons for clarity
- Use horizontal layout for feature/spotlight cards at wider breakpoints

### ❌ Don't

- Don't nest interactive elements (buttons, links) inside a card-as-link (`href` set)
- Don't use cards for single-line items (use a list instead)
- Don't override card background with inline styles — use surfaces
- Don't omit headings; they provide landmark structure
- Don't use cards for form inputs or complex interactions
